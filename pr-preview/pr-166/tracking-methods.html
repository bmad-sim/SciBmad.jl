Tracking Methods¶

Every element has a tracking_method, which sets how particles are pushed through it. When you construct an element with one of the element kinds, a suitable tracking method is chosen for you (see the table of Element Kinds), for example MatrixKick() for a Quadrupole and BendKick() for an SBend. Any element with L = 0 uses Exact().

A bare LatElement() has no tracking method, so you must set one yourself before tracking through it. The default can always be overridden, either during construction or afterwards:

qf = Quadrupole(L=0.5, Kn1=0.36, tracking_method=DriftKick(order=6))
qf.tracking_method = MatrixKick()

MatrixKick(order=4, opt_scheme=true)

Since any element can contain any combination of parameters, not every tracking method can handle every element. If it can’t, tracking stops with an error telling you which tracking method to use instead. For example, DriftKick cannot track through a solenoid field:

d = Drift(L=1.0, Ksol=0.1)
bl = Beamline([d], species_ref=Species("electron"), pc_ref=1e9)
track(bl, v0=zeros(1, 6))

DriftKick is not compatible in element with solenoidal multipole component. Try SolenoidKick instead

Integration Steps and Slices¶

The tracking method decides how each integration step is taken. How many steps are taken, and a few other settings, are set in the element’s UniversalParams:

  • n_steps or ds_step: the number of integration steps, or the length of each step. Setting one of these sets the other (n_steps = ceil(L / n_slices / ds_step)).

  • n_slices: the number of slices to split the element into, each with n_steps integration steps. Collective effects (see Collective Effects) and a ramping reference energy are recomputed and applied once per slice. If you only need more accuracy, increase n_steps instead, which is faster.

  • fringe_at: which ends of the element include fringe fields. Fringe fields are only included at the ends of the whole element, not between its slices.

  • rad_damping and rad_fluctuations: whether the element includes the damping and the stochastic fluctuations of synchrotron radiation.

sf = Sextupole(L=0.2, Kn2=1.2, n_steps=4, rad_damping=true)

LatElement:

   kind             = "Sextupole"        Kn2   = 1.2

Patches, maps, and SaganCavity (whose kicks are set by n_cells) are always tracked in one step, so n_steps must be 1 for them. Elements with a patch or a map, and SaganCavity, also cannot be sliced.

Symplectic Integrators¶

DriftKick, MatrixKick, BendKick, SolenoidKick, and Implicit are symplectic integrators. The first four split the motion through the element into a simple part that can be solved directly, and “kicks” with the rest in between. They differ in how the motion is split:

  • DriftKick: drifts exactly, and kicks with all of the multipoles. This works for any straight element without a solenoid field, including RF cavities.

  • MatrixKick: tracks an approximate energy-dependent quadrupole, and kicks with its corrections and other multipoles. This is usually the best choice for straight elements with a strong quadrupole field.

  • SolenoidKick: tracks through the solenoid field exactly, and kicks with the rest of the multipoles. This works for any straight element, with or without a solenoid field, including RF cavities.

  • BendKick: tracks through the bend exactly, and kicks with the rest of the multipoles. This is the usual choice for elements that bend the reference trajectory (see BendParams).

  • Implicit: an implicit integrator for arbitrary electromagnetic fields defined by a four-potential (see FourPotentialParams). All fields in the element must be included in the four-potential.

All of these take the same two settings:

DriftKick — Type.

DriftKick(; order=4, opt_scheme=true)

Symplectic integrator using a drift-kick Hamiltonian split.

Properties

  • order: Order of the integrator, supported are orders 2, 4, 6, 8, and 10. Default is 4

  • opt_scheme: If true, uses an optimized integration scheme, else uses the standard Yoshida scheme. Default is true

Implicit also has use_newton:

Implicit — Type.

Implicit(; order=4, opt_scheme=true, use_newton=false)

Implicit symplectic integrator for arbitrary electromagnetic potentials.

Properties

  • order: Order of the integrator, supported are orders 2, 4, 6, 8, and 10. Default is 4

  • opt_scheme: If true, uses an optimized integration scheme, else uses the standard Yoshida scheme. Default is true

  • use_newton: If true, Newton’s method is used to solve the implicit step, else fixed point iteration is used. Default is false

A higher order integrator is more accurate per step, but each step takes longer: with the optimized schemes, an order 4 step is made of 5 second order steps, and an order 6 step of 13. Whether you get more accuracy for the same speed by increasing the order or by increasing the number of steps depends on the element, so it is worth checking for your lattice.

If an element is a pure drift, a pure bend, or a pure solenoid, it is tracked through exactly, and the order and number of steps don’t change the result. The exception is when radiation is included, because the radiation is applied at each integration step. The steps are still taken in any case, so callbacks (e.g. used by twiss to compute the Twiss parameters inside elements) are executed at every step.

Exact¶

Exact — Type.

Exact()

Tracking method specifying “exact” transformations, e.g. patches, custom maps, thin multipoles, etc.

Exact is used for elements that are not integrated in steps: patches, maps, markers, and thin (zero length) multipoles. It can also track exactly through a nonzero length element with no field (a drift), only a solenoid field, only a dipole field (also in a bend), or only an electric dipole field (EMultipoleParams). Setting the length of an element to zero switches its tracking method to Exact automatically.

Runge Kutta¶

RK4 — Type.

RK4()

Fourth order Runge Kutta integrator, not symplectic.

RK4 integrates the equations of motion through an arbitrary electromagnetic field, defined as a function of the particle position and time in EMFieldParams, together with any multipoles and bend in the element. It is not symplectic, and does not support spin tracking.

Sagan Cavity¶

SaganCavity — Type.

SaganCavity(; n_cells = -1, L_active = -1.0)

Integrator for RF cavities using the Sagan Cavity model.

Properties

  • n_cells: Number cells in the cavity. If negative, then the approximate half wavelength between cells is used, and if zero then a single kick is applied. Default is -1

  • L_active: Active length of the cavity. If negative, then the element length is used. Default is -1

See SaganCavity Tracking for how to use it, and SaganCavity Physics for the model.
