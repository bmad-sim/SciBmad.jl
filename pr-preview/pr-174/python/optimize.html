Matching and Optimization¶

Matching means varying parameters of a lattice (the “knobs”) until quantities such as the tunes, the beta functions at some point, chromaticities, etc have the values you want. In SciBmad all you need to do is write down the quantities and their goals, say what knobs should be varied to achieve that goal, and call sb.match.

Most optimizers need the derivatives of the quantities with respect to the knobs. In non-differentiable codes, these are computed with finite differences, which are approximate and need one more calculation per knob. Because SciBmad is fully differentiable, match! gets the exact derivatives with respect to all knobs from a single calculation.

A First Match¶

Let’s make the phase advance of a FODO cell \(90^\circ\) in both planes by varying its two quadrupoles.

import numpy as np
import scibmad as sb

with sb.elements():
    qf = sb.Quadrupole(Kn1=0.36, L=0.5)
    sf = sb.Sextupole(Kn2=1.2, L=0.2)
    d = sb.Drift(L=0.2)
    b = sb.SBend(L=6.5, angle=np.pi/132)
    qd = sb.Quadrupole(Kn1=-0.36, L=0.5)
    sd = sb.Sextupole(Kn2=-1.2, L=0.2)

fodo = sb.Beamline([qf, sf, d, b, d, qd, sd, d, b, d],
                   species_ref=sb.Species("electron"), pc_ref=18e9)

First we need a way to refer to what twiss computes for fodo: TwissExpr gives exactly that. It is a lazily-evaluated twiss call that can be read in the same way that twiss can, however nothing is actually computed until it is requested. Furthermore, it will automatically infer the at, cols, base_cols, as_taylor_series and GTPSA_descriptor keyword arguments to twiss based on what you request. Other than those inputs, TwissExpr accepts all the same arguments as twiss.

tw = sb.TwissExpr(fodo)
tw

res = sb.match(vary=[sb.Knob(qf, "Kn1"), sb.Knob(qd, "Kn1")],

sb.undo(res) would set the knobs back to where they were, and sb.match(res) continues a match that stopped early.

If only one beamline is involved, it can also be given to sb.match directly. The targets are then written as a function of its TwissExpr. Keyword arguments for twiss, if any, are given with twiss=dict(rf_on=False):

sb.match(fodo, vary=[sb.Knob(qf, "Kn1"), sb.Knob(qd, "Kn1")],
         targets=lambda tw: [tw.q1 == 0.25, tw.q2 == 0.25])

Quantities and Locations¶

Every summary value and every numeric column of twiss is available from a TwissExpr, written in the same way as for the result of twiss: tw.q1, tw.dq1, tw.q1(J1=1), tw.beta1[qd], tw.beta1[qd, "exit"], tw.beta1[[b], :], tw.beta1["q*"], tw.dbeta1[qd], tw.h3000[1], and so on. Unlike for twiss, you do not choose truncation orders or rows: TwissExpr will knows what you need based on what you ask for.

You can form arbitrary expressions with the Twiss output to serve as targets/minimization goals using ordinary arithmetic and functions. For example, the square of the beta function at qd minus five times the average of the alpha function through the bends:

e = tw.beta1[qd]**2 - 5*sb.mean(tw.alpha1[[b], :])
e

beta1[qd#6]^2 - (5 * (sum(alpha1[b#4], alpha1[d#5], alpha1[b#9], alpha1[d#10]) / 4))

The h terms are complex numbers. value gives them as such, but a target or minimize needs their real and imag parts separately.

value computes an expression. Only the rows and columns of twiss that it needs are computed:

sb.value(e)

21.372935387635394

A location with several places gives a vector, and arithmetic and comparisons apply to each of its entries. sb.sum, sb.mean, sb.maximum, and sb.minimum reduce it to one expression (they are Julia’s functions, which build an expression, not Python’s):

sb.value(tw.beta1["q*"])  # beta1 at qf and at qd

array([25.1305588 ,  4.60852485])

sb.value(sb.maximum(tw.beta1[:]))

25.130558796383323

A phase advance between two points is simply a difference:

sb.value(tw.phi1[qd] - tw.phi1[qf])  # in units of 2π

0.11776925185765874

Anything else can be included with lazy: sb.lazy(f) is the result of the function f(), computed from the lattice itself when it is needed. For example, the field gradient of qf in this beamline:

sb.value(sb.lazy(lambda: fodo[1].Bn1))

-22.842477272525

Targets¶

Besides ==, a target can be an inequality:

tw.beta1[qd] <= 30
tw.beta1["q*"] <= 30              # at each of these elements
sb.maximum(tw.beta1[:]) <= 100    # everywhere

An inequality only acts while it is violated. A target counts as met when it is within its tolerance, which is 1e-8 unless you set it with Target. A weight makes a target count more or less than the others while they cannot all be met:

sb.Target(tw.q1, 0.25, tol=1e-6)
sb.Target(tw.beta1[qd], lower=5, upper=30, weight=0.1)

There may be fewer, as many, or more targets than knobs. With more knobs than needed, many solutions exist, and match! returns one near the starting point: each step is the smallest change of the knobs that meets the targets to first order. With more targets than can be met, match! returns the closest it can get (in the least-squares sense) and reports the match as not converged.

minimize is for quantities that should just be as small as possible. For example, we can minimize the driving terms of a ring with four sextupoles while also requiring that the chromaticities are +1 with (using sb.reim which returns a tuple of the real and imaginary parts, and then unpacking those values with * into the list):

twc = sb.TwissExpr(ring, rf_on=False)
sb.match(vary=[sb.Knob(s, "Kn2") for s in (s1, s2, s3, s4)],
         targets=[sb.Target(twc.dq1, 1, weight=100, tol=1e-4),
                  sb.Target(twc.dq2, 1, weight=100, tol=1e-4)],
         minimize=[*sb.reim(twc.h3000[1]), *sb.reim(twc.h2100[1]), *sb.reim(twc.h1020[1])])

The sum of the squares of the expressions in minimize and of the distances from the targets (each times its weight) is made as small as possible. If they cannot all vanish, the result balances them, so give targets that must hold a larger weight, as here.

Knobs¶

A knob is any parameter that can be set with object.parameter = value:

sb.Knob(qf, "Kn1")                          # an element parameter
sb.Knob(qf, "Kn1", lower=0, upper=0.6)      # with bounds
sb.Knob(d, "L")                             # also lengths
sb.Knob(ring.context, "kqf")                # a variable used by deferred expressions
sb.Knob(ring.context, "coilstrengths")      # a vector variable: one knob per entry
sb.Knob(ring.context, "coilstrengths", 2)   # one entry of it (the 2nd, counted from 1)

sb.Knob(qf, "Kn1") is Julia’s @knob qf.Kn1 (Python cannot capture qf.Kn1 itself: it would be the number). Setting a parameter of an element changes it everywhere the element is placed (see Defining a Beamline), so sb.Knob(qf, "Kn1") varies all qfs together.

To vary several different elements together, or to build any other knob, use a deferred expression and vary the variable it depends on:

qf.Kn1 = sb.DefExpr(lambda c: c.kq)
qd.Kn1 = sb.DefExpr(lambda c: -c.kq)
fodo.context.kq = 0.38

res = sb.match(vary=[sb.Knob(fodo.context, "kq")], targets=[tw.q1 == 0.25])
res

Match converged (all targets met): 2 iterations, 3 evaluations, 0.129 s
 Target  value  goal     met
 q1      0.25   == 0.25  yes
 Knob  before  after         lower  upper
 kq    0.38    0.3804135072  -Inf   Inf

A variable can also be a vector, e.g. the strengths of many correctors, each set by a deferred expression such as sb.DefExpr(lambda c: c.coilstrengths[2]) (the third entry: entries of a vector variable are counted from 0 in Python, as in the NumPy array ring.context.coilstrengths). sb.Knob(ring.context, "coilstrengths") then varies every entry. The result lists them as coilstrengths[1], coilstrengths[2], and so on (the names count from 1, as Julia does, and so does the third argument of sb.Knob, the entry), as many as fit in the terminal. print(res) shows all of them.

step limits how much a knob may change in one iteration (sb.Knob(qf, "Kn1", step=0.01)). A knob is also an expression, so it can appear in targets: sb.Knob(qf, "Kn1") + sb.Knob(qd, "Kn1") <= 0.05.

Orbit Correction¶

The closed orbit is a column of twiss like any other (tw.x[bpm], tw.y[bpm], …), so sb.match can do orbit correction too. Here is a ring of ten cells, each with a misaligned quadrupole, a horizontal corrector and a BPM. The strengths of all correctors come from one vector variable of the context, kicks (and gradient errors of the quadrupoles from another, dk, used below):

ncell = 10
offsets = 1e-4 * np.array([0.8, -1.2, 0.3, 1.5, -0.6, 0.9, -1.1, 0.2, 1.3, -0.4])  # in m
elements = []
bpms = []
for i in range(ncell):
    bpm = sb.Marker()
    bpms.append(bpm)
    elements += [sb.Quadrupole(Kn1=sb.DefExpr(lambda c: 0.36 + c.dk[i]), L=0.5,
                               x_offset=offsets[i]),
                 sb.Multipole(Kn0L=sb.DefExpr(lambda c: c.kicks[i])), sb.Drift(L=0.2), bpm,
                 sb.SBend(L=6.5, angle=np.pi/ncell), sb.Drift(L=0.2),
                 sb.Quadrupole(Kn1=-0.36, L=0.5), sb.Drift(L=0.2),
                 sb.SBend(L=6.5, angle=np.pi/ncell), sb.Drift(L=0.2)]
ring = sb.Beamline(elements, species_ref=sb.Species("electron"), pc_ref=18e9)
ring.context.kicks = np.zeros(ncell)
ring.context.dk = np.zeros(ncell)

twr = sb.TwissExpr(ring)
orbit = [twr.x[bpm] for bpm in bpms]
np.max(np.abs(sb.value(orbit)))  # 5.8e-4 m at the BPMs

np.float64(0.0005790402437629866)

minimize makes the orbit at the BPMs as small as possible (in the least-squares sense), varying every corrector:

res = sb.match(vary=[sb.Knob(ring.context, "kicks")], minimize=orbit)
np.max(np.abs(sb.value(orbit)))  # 3e-15 m

np.float64(5.326205571531729e-15)

Only the orbit is computed for this (none of the optics at the BPMs), which is faster. The closed orbit needs stable linear optics: if the errors make the ring unstable, correct the orbit first with the sextupoles turned off, then turn them on in steps.

The orbit response matrix, the change of the orbit at each BPM per kick of each corrector, is a matrix of derivatives (deriv, see “Values and Derivatives” below), here with respect to the entries of kicks:

R = np.array([[sb.deriv(twr.x[bpm], sb.Knob(ring.context, "kicks", j))
               for j in range(1, ncell + 1)] for bpm in bpms], dtype=object)

A measured response matrix can then be fitted, as in LOCO. It depends on the focusing of the ring, and hardly on the misalignments: they shift the orbit, but without sextupoles they barely change its response to a kick (here by 2e-4 of its size). So it is fitted with gradient errors.

Here the “measurement” is the response matrix of the ring with the gradient errors dk_true. The model starts without them, and finds them again:

dk_true = 1e-3 * np.array([1.0, -2.0, 0.5, 1.5, -1.0, 0.8, -0.3, 2.0, -1.2, 0.4])
ring.context.dk = dk_true.copy()
R_measured = sb.value(R)
ring.context.dk = np.zeros(ncell)

targets = [r == m for r, m in zip(R.ravel(order="F"), R_measured.ravel(order="F"))]
res = sb.match(vary=[sb.Knob(ring.context, "dk")], targets=targets)
np.max(np.abs(ring.context.dk - dk_true))  # 5e-16: the errors are found again

np.float64(2.7777259659078624e-16)

Further knobs fit the same way, for example quadrupole tilts for the coupling (with the vertical orbit in the matrix) and the calibrations of the BPMs and correctors.

Lines That Are Not Periodic¶

For a transfer line, a linac, or a section of a ring by itself, give the lattice functions at its start with initial or a_initial (see Open lines). a_initial can be the a of another TwissExpr, so that the line continues from another beamline. Here a line of four quadrupoles follows the FODO cell, and is matched to a waist with beta functions of 10 m at its end:

with sb.elements():
    m1 = sb.Quadrupole(Kn1=0.3, L=0.5)
    m2 = sb.Quadrupole(Kn1=-0.3, L=0.5)
    m3 = sb.Quadrupole(Kn1=0.3, L=0.5)
    m4 = sb.Quadrupole(Kn1=-0.3, L=0.5)
    dm = sb.Drift(L=3.0)

line = sb.Beamline([m1, dm, m2, dm, m3, dm, m4, dm],
                   species_ref=sb.Species("electron"), pc_ref=18e9)

# starts with the periodic lattice functions of the cell:
tl = sb.TwissExpr(line, a_initial=tw.a[-1])

res = sb.match(vary=[sb.Knob(m, "Kn1") for m in (m1, m2, m3, m4)],
               targets=[tl.beta1[-1] == 10, tl.beta2[-1] == 10,
                        tl.alpha1[-1] == 0, tl.alpha2[-1] == 0])
res

ini = sb.Context(beta1=10.0, alpha1=0.0, beta2=10.0, alpha2=0.0)

res = sb.match(vary=[sb.Knob(ini, p) for p in ("beta1", "alpha1", "beta2", "alpha2")],

Values and Derivatives¶

sb.value_and_jacobian gives the values of expressions and their exact derivatives with respect to knobs, for your own purposes (in Julia it is SciBmad.value_and_jacobian, which is not exported):

v, J = sb.value_and_jacobian([tw.beta1[qd], tw.q1], [sb.Knob(qf, "Kn1"), sb.Knob(qd, "Kn1")])
J  # [[dbeta1/dqf, dbeta1/dqd], [dq1/dqf, dq1/dqd]]

array([[-29.23630458,  -0.5737466 ],
       [  1.01592676,   0.18013615]])

deriv(expr, knob) is the derivative of an expression with respect to a knob as a new expression, as for the orbit response matrix above. Such derivatives can be used like any other expression, also in targets. For more, see Parametric Normal Form.

Using Other Optimizers¶

sb.match takes Gauss-Newton steps, which find a nearby solution. With solver="levenberg_marquardt" it uses the Levenberg-Marquardt method of BatchSolve instead. Like every such method, it can stop at a point that small changes cannot improve, even though a solution exists elsewhere. A better starting point, bounds on the knobs, or a global optimizer then help.

For other optimizers, MatchProblem provides what the optimization packages of Python (e.g. SciPy) ask for:

qf.Kn1 = 0.36
qd.Kn1 = -0.36
prob = sb.MatchProblem(vary=[sb.Knob(qf, "Kn1", lower=0.2, upper=0.6),
                             sb.Knob(qd, "Kn1", lower=-0.6, upper=-0.2)],
                       targets=[tw.q1 == 0.25, tw.q2 == 0.25])
prob

MatchProblem with 2 knobs, 2 targets

  • prob.x, prob.lower, prob.upper: the current values and the bounds of the knobs

  • sb.value(prob, x): the vector of the distances from the targets, at the knob values x

  • sb.value_and_jacobian(prob, x): these and their exact derivatives with respect to the knobs

  • sb.penalty(prob, x): one number, the sum of the squared distances. It is inf where the lattice has no solution, for example where it is unstable

  • sb.setknobs(prob, x): sets the knobs

value, value_and_jacobian and penalty set the knobs to x, so the lattice is left at the last x an optimizer tried. Finish with sb.setknobs at the solution, as below.

For example, with the least-squares solver least_squares of SciPy:

from scipy.optimize import least_squares

sol = least_squares(lambda x: sb.value(prob, x), prob.x,
                    jac=lambda x: sb.value_and_jacobian(prob, x)[1])
sb.setknobs(prob, sol.x)
sb.twiss(fodo, at=[])

Twiss:
summ:
 q1     = 0.2500000000001255
 q2     = 0.2500000000001256
 etac   = 0.0010780794265294214
 alphac = 0.0010780802324551232

df:
0×26 DataFrame
 Row │ index  name  kind  s    beta1  phi1  dx   x    beta2  phi2  dy   y    slip  alpha1  alpha2  ⋯
     │                    [m]  [m]    [2π]  [m]  [m]  [m]    [2π]  [m]  [m]  [m]   [1]     [1]     ⋯
─────┴──────────────────────────────────────────────────────────────────────────────────────────────
                                                                                  11 columns omitted

With the gradient-based L-BFGS-B of SciPy’s minimize:

from scipy.optimize import minimize

def gradient(x):  # gradient of the penalty
    r, J = sb.value_and_jacobian(prob, x)
    return 2 * J.T @ r

res = minimize(lambda x: sb.penalty(prob, x), prob.x, jac=gradient, method="L-BFGS-B")
sb.setknobs(prob, res.x)

And with a genetic algorithm that needs no derivatives, here SciPy’s differential evolution, within the bounds of the knobs:

from scipy.optimize import differential_evolution

bounds = list(zip(prob.lower, prob.upper))
res = differential_evolution(lambda x: sb.penalty(prob, x), bounds)
sb.setknobs(prob, res.x)

Such a global search can be finished with sb.match(prob), which then starts from its result.

How It Works¶

The knobs are made parameters of the truncated power series that twiss computes with (see Parametric Normal Form), with the truncation orders that the quantities and their derivatives need. One twiss calculation per TwissExpr then gives the values and all derivatives, and the lattice is restored afterwards. While this runs, the lattice holds these parameters, so match, value and value_and_jacobian must not be used from several threads at once on the same lattice.

Making a parameter a knob sets it, as qf.Kn1 = 0.38 does. If the parameter was set to a deferred expression, that dependence is then broken, also by value and value_and_jacobian. To keep it, vary the variable the expression depends on. Deferred expressions and contexts that knobs act through must not be restricted to a number type such as DefExpr{Float64} or Context{Float64}.

match! — Function.

match!(; vary, targets=[], minimize=[], kwargs...) -> MatchResult
match!(bl::Beamline; vary, targets, twiss=(;), kwargs...)
match!(prob::MatchProblem; kwargs...)
match!(res::MatchResult; kwargs...)

Varies the Knobs vary (also obj => :property pairs) until the Targets targets are met, and leaves the lattice there. minimize are expressions whose sum of squares is made as small as possible together with the distances from the targets (each times its weight; the expressions times minimize_weight, default 1). Targets are written with expressions (LatticeExpr) of the quantities of a TwissExpr:

tw = TwissExpr(cell)
match!(vary=[@knob(qf.Kn1), @knob(qd.Kn1)], targets=[tw.q1 == 0.25, tw.q2 == 0.25])

Given a Beamline, targets (and minimize) may be functions of its TwissExpr (made with the twiss keyword arguments in twiss), which can also be written as a do block:

match!(cell; vary=[@knob(qf.Kn1), @knob(qd.Kn1)], targets = tw -> [tw.q1 == 0.25, tw.q2 == 0.25])

The derivatives are exact (see SciBmad.value_and_jacobian). Each step is a Gauss-Newton step from the singular value decomposition of the Jacobian: the smallest change of the knobs that meets the targets to first order. Steps that do not reduce the residuals, or where the lattice has no solution (e.g. it is unstable), are rejected and shorter or damped ones taken, so there may be fewer, as many, or more targets than knobs. Knobs stay within their bounds and step limits, and <= and >= targets only count while they are violated. Like every such method it finds a nearby solution: targets of very different size (a tune and a beta function) should get weights that make their residuals comparable. To use another optimizer, see MatchProblem.

Keyword arguments

  • maxiter: Maximum number of iterations, default is 50

  • verbose: If true, prints the progress of the solver at each iteration. Default is false

  • solver: :gauss_newton (default): Gauss-Newton steps from the singular value decomposition of the Jacobian (their halves, quarters and eighths, then damped steps, where a step does not reduce the residuals), or :levenberg_marquardt: the Levenberg-Marquardt method of BatchSolve (BatchSolve.levenberg_marquardt!)

  • rcond: For solver=:gauss_newton, singular values of the Jacobian below rcond times the largest are ignored (knob combinations the targets do not respond to). Default is 1e-10

Returns a MatchResult. match!(res) continues the match from the current lattice.

TwissExpr — Type.

TwissExpr(bl::Beamline; kwargs...)

The quantities of twiss(bl; kwargs...) as expressions (LatticeExpr), computed only when they are needed (by value, SciBmad.value_and_jacobian or match!), and then only at the locations used. kwargs are those of twiss (rf_on, a_initial, spin, delta0, …) except at, cols, base_cols, as_taylor_series and GTPSA_descriptor, which are set from the expressions. The truncation orders are chosen from the quantities used; order can be given to use a higher one.

a_initial may be the a of another TwissExpr, e.g. TwissExpr(line; a_initial=tw.a[end]), to continue the lattice functions of another beamline. initial may be a Context, whose variables can then be knobs, e.g. to match the Twiss parameters at the start of a line: ini = Context(beta1=10.0, beta2=10.0), TwissExpr(line; initial=ini), @knob(ini.beta1).

Quantities

  • Summary values: tw.q1, tw.q2, tw.q3, tw.etac, tw.alphac, tw.qspin, tw.damp1, … A derivative of an amplitude-dependent value is selected as for the result of twiss, e.g. tw.q1[delta=2] (∂²q1/∂δ²) or tw.q1[J1=1]; tw.dq1 and tw.dq2 are short for the chromaticities tw.q1[delta=1] and tw.q2[delta=1], tw.dq1_n for tw.q1[delta=n].

  • Columns: tw.<column>[location] for every scalar column of twiss, including chromatic derivatives (tw.dbeta1, tw.dx_2) and tw.h<ijkl>.

Locations

The same as for the columns of the result of twiss (see TwissColumn):

  • tw.beta1[ele], tw.beta1[7]: the beginning of the element (placed once, else an error), or of the element with that beamline index. tw.beta1[[ele]]: every placement (a vector).

  • tw.beta1[ele, :exit]: the end of the element.

  • tw.beta1[ele, :]: every integration step of the element, both ends included (a vector; tw.beta1[[ele], :] of every placement). tw.beta1[ele, k]: after k integration steps.

  • tw.beta1[end], tw.beta1[begin]: the end and the beginning of the beamline (or of the part given with start and stop, which vectors are restricted to). end is a beamline index: tw.beta1[end-1] is the beginning of the last element.

  • tw.beta1["q*"], tw.beta1[r"..."]: elements by name, as for findelements (a vector).

  • tw.beta1[(s1, s2)], tw.beta1[:]: every integration step in an s-range, or of the whole beamline (a vector).

Vectors are elementwise: tw.beta1["q*"]^2, tw.beta1["q*"] <= 30 (one target per element), with sum, mean, maximum, minimum and norm.

Knob — Type.

Knob(obj, property; lower=-Inf, upper=Inf, step=Inf, name)
Knob(obj, property, index; lower=-Inf, upper=Inf, step=Inf, name)
Knob(get, set; lower=-Inf, upper=Inf, step=Inf, name="knob")
@knob obj.property lower=... upper=...
@knob obj.property[index] lower=... upper=...

Something that can be varied: the property of obj (a LatElement, a Context, a Controller, or anything else with obj.property to get and set a number), or a pair of functions get() and set(value). lower and upper are the bounds used by match! and step the largest change per iteration.

If the property is a vector of numbers (e.g. a variable of a Context holding the strengths of several correctors), the knob stands for one knob per entry, named property[1], property[2], …, with the same bounds: match!, value_and_jacobian and setknobs! vary each entry. index (or @knob obj.property[index]) is one entry alone.

A Knob is also a LatticeExpr, so it can be used in expressions and targets.

Making a property a knob sets it, as obj.property = value does: if it was set to a deferred expression, that dependence is replaced by the value.

Examples

k1 = Knob(qf, :Kn1; lower=0, upper=1)
k2 = @knob ring.context.kqd
k3 = @knob ring.context.coilstrengths # one knob per entry of the vector
k4 = @knob ring.context.coilstrengths[2]

Target — Type.

Target(expr, value; tol=1e-8, weight=1, name)
Target(expr; lower=-Inf, upper=Inf, tol=1e-8, weight=1, name)
expr == value,  expr <= value,  expr >= value

A goal for match!: the expression (LatticeExpr) expr should equal value, or lie between lower and upper. The target is met when it is within tol. weight multiplies its residual, to make it count more or less than the other targets while they are not all met.

value — Function.

value(expr)
value(exprs::AbstractArray)

The current value of the expression (LatticeExpr) expr, or of each expression of an array (complex for an h term). Each TwissExpr used is computed with one twiss call, only at the locations and with the columns the expressions use.

SciBmad.value_and_jacobian — Function.

SciBmad.value_and_jacobian(exprs, knobs) -> (values, jacobian)
SciBmad.value_and_jacobian(exprs, knobs, x) -> (values, jacobian)

Not exported, because DifferentiationInterface exports a function of the same name: call it as SciBmad.value_and_jacobian.

The current values of the expressions (LatticeExprs) exprs and their exact derivatives in the knobs (Knobs, or obj => :property pairs): jacobian[i, j] is the derivative of exprs[i] (in the order of vec(exprs)) in knobs[j]. For a single expression, the value and its gradient are returned. With x, the knobs are first set to the values x (and stay there).

The derivatives are computed by automatic differentiation: the knobs are made parameters of the truncated power series (GTPSA) of one twiss call per TwissExpr, with the truncation orders the expressions need, and the knobs are set back to their values afterwards.

MatchProblem — Type.

MatchProblem(; vary, targets=[], minimize=[], minimize_weight=1)

A matching/optimization problem: the Knobs vary (or obj => :property pairs), the Targets to meet, and expressions minimize whose sum of squares should be as small as possible. match! solves it with its built-in solver. To use any other optimizer:

  • prob.x, prob.lower, prob.upper: the current values and the bounds of the knobs

  • value(prob, x): the residual vector at the knob values x: for each target its weight times its distance from its goal (zero where it is met), then minimize_weight times each expression to minimize

  • SciBmad.value_and_jacobian(prob, x): the residuals and their exact Jacobian in the knobs

  • penalty(prob, x): the sum of the squared residuals, Inf where the lattice has no solution (for optimizers that take a scalar and no derivatives, e.g. genetic algorithms)

  • setknobs!(prob, x): sets the knobs

These functions leave the knobs at x.

The sum of the squared residuals is what is minimized, so targets and expressions to minimize are balanced against each other when they cannot all vanish. Larger target weights (or a smaller minimize_weight) hold the targets more tightly.
