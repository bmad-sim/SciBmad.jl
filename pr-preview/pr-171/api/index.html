SciBmad.AmplitudeDependentValue — Type
AmplitudeDependentValue

A value for the whole ring (e.g. a tune) as a Taylor series in δ (or the longitudinal action J₃ with synchrotron motion) and the actions J₁, J₂, and in GTPSA parameters if there are any.

  • q[delta=2], q[J1=2, J2=1]: a derivative, here ∂²q/∂δ² and ∂³q/∂J₁²∂J₂ (q[delta=1] is the chromaticity)
  • getterm(q; delta=2): the coefficient of that term of the Taylor series, i.e. the derivative divided by the factorials (∂²q/∂δ²/2), as the series is printed

With as_taylor_series=true the result is a Taylor series in the GTPSA parameters.

SciBmad.Knob — Type
Knob(obj, property; lower=-Inf, upper=Inf, step=Inf, name)
Knob(obj, property, index; lower=-Inf, upper=Inf, step=Inf, name)
Knob(get, set; lower=-Inf, upper=Inf, step=Inf, name="knob")
@knob obj.property lower=... upper=...
@knob obj.property[index] lower=... upper=...

Something that can be varied: the property of obj (a LatElement, a Context, a Controller, or anything else with obj.property to get and set a number), or a pair of functions get() and set(value). lower and upper are the bounds used by match! and step the largest change per iteration.

If the property is a vector of numbers (e.g. a variable of a Context holding the strengths of several correctors), the knob stands for one knob per entry, named property[1], property[2], ..., with the same bounds: match!, value_and_jacobian and setknobs! vary each entry. index (or @knob obj.property[index]) is one entry alone.

A Knob is also a LatticeExpr, so it can be used in expressions and targets.

Making a property a knob sets it, as obj.property = value does: if it was set to a deferred expression, that dependence is replaced by the value.

Examples

k1 = Knob(qf, :Kn1; lower=0, upper=1)
k2 = @knob ring.context.kqd
k3 = @knob ring.context.coilstrengths # one knob per entry of the vector
k4 = @knob ring.context.coilstrengths[2]

SciBmad.LatticeExpr — Type
LatticeExpr

An expression of lattice quantities: a quantity of a TwissExpr (tw.beta1[ele]), a Knob, or arithmetic and functions of them (tw.beta1[ele]^2 - 5*mean(tw.alpha1[ele, :])). It is computed by value, SciBmad.value_and_jacobian or match!.

SciBmad.MatchProblem — Type
MatchProblem(; vary, targets=[], minimize=[], minimize_weight=1)

A matching/optimization problem: the Knobs vary (or obj => :property pairs), the Targets to meet, and expressions minimize whose sum of squares should be as small as possible. match! solves it with its built-in solver. To use any other optimizer:

  • prob.x, prob.lower, prob.upper: the current values and the bounds of the knobs
  • value(prob, x): the residual vector at the knob values x: for each target its weight times its distance from its goal (zero where it is met), then minimize_weight times each expression to minimize
  • SciBmad.value_and_jacobian(prob, x): the residuals and their exact Jacobian in the knobs
  • penalty(prob, x): the sum of the squared residuals, Inf where the lattice has no solution (for optimizers that take a scalar and no derivatives, e.g. genetic algorithms)
  • setknobs!(prob, x): sets the knobs

These functions leave the knobs at x.

The sum of the squared residuals is what is minimized, so targets and expressions to minimize are balanced against each other when they cannot all vanish. Larger target weights (or a smaller minimize_weight) hold the targets more tightly.

SciBmad.MatchResult — Type
MatchResult

The result of match!: converged (all targets met), status, iterations, the knob values before and after (x0, x), the values of the target expressions (values), the sum of squared residuals after each iteration (history), and the problem. undo!(res) sets the knobs back to x0; match!(res; kwargs...) continues.

SciBmad.Target — Type
Target(expr, value; tol=1e-8, weight=1, name)
Target(expr; lower=-Inf, upper=Inf, tol=1e-8, weight=1, name)
expr == value,  expr <= value,  expr >= value

A goal for match!: the expression (LatticeExpr) expr should equal value, or lie between lower and upper. The target is met when it is within tol. weight multiplies its residual, to make it count more or less than the other targets while they are not all met.

SciBmad.TrackColumn — Type
TrackColumn

A quantity of a TrackResult (e.g. res.x), read at locations of the beamline as the columns of twiss (see TwissColumn), and for a saved turn and a particle given with the keywords turn (the turn number, 0 for the initial coordinates) and particle, written after the location (or alone):

  • res.x[]: without a location, at the only saved location (by default the end of the beamline; with several saved locations, one must be given), [particle, saved turn]
  • res.x[turn=n]: all particles after turn n, res.x[turn=n, particle=i]: one number. turn and particle can also be : (all, as without them), a range or a vector
  • res.x[qd, turn=n], res.x[5, ...], res.x[qd, :exit, ...], res.x[end, ...]: at the beginning of qd (placed once) or of the element with beamline index 5, at its end, at the end of the beamline (end is the beamline index of the end, one more than the number of elements)
  • res.x[qd, :], res.x[[qd]], res.x["q*"], res.x[(2.0, 6.0)]: at several locations (every step of qd, every placement of qd, ...; as for twiss): their index comes after the particle ([particle, location, saved turn])

res.v, res.q and the spins from track_spin have the coordinate, quaternion or spin component as the index after the particle, and t_ref and beta_gamma_ref no particle index (unless they are per particle). The locations must have been saved (see at in track).

SciBmad.TrackConfig — Type
struct TrackConfig

Defines configuration settings for a particles tracking run.

Properties

  • n_turns::Int: Number of turns, defaults to 1
  • save_every_n_turns::Int: Multiple of turn number which specifies the turns tracking data is saved, defaults to 1
  • in_body_coordinates::Bool: If true, particles saved inside misaligned elements are not transformed back to the reference curve coordinates. Default is false
  • save_reference::Bool: If true, the reference time and energy at each location and saved turn are saved too (t_ref and beta_gamma_ref of the result). This compiles the tracking separately and makes it slower (the reference time is computed at every integration step). Default is false
  • scalar_params::Bool: If true, only uses the primal values of any LatElement properties set as GTPSA.TPS, ForwardDiff.Dual, or ReverseDiff.TrackedReal (ignores derivatives part, useful for closed orbit finding prior to parametric normal form). Default is false
  • rf_on::Bool: If false, then any RFParams in any LatElements are ignored for the entirety of the tracking. Default is true
  • ramp_particle_energy_without_rf::Bool: If true when ramping (Beamline's reference energy is a TimeFunction), then particle energies will be artificially ramped with the reference energy. Default is false
  • ramp_update_each_particle::Bool: If true when ramping, then each particle sees the reference energy at its own time (from its z-offset) at the element entrances, and the reference energy also changes through each element. If false, all particles see the reference energy at the reference time at each element entrance. Usually only needed if ramping is fast compared to the time scale of bunch passage through elements. (Time-dependent element parameters are always evaluated at each particle's own time.) Default is false.
  • batch_start::Int: Specifies the starting index for BatchParams that particles in a bunch will see. E.g., if batch_start=3, then particle 1 sees index 3 in all BatchParams, particle 2 sees index 4, etc. Indexing of BatchParams will loop around to the start if the particle index exceeds the length of the BatchParams. Default is 1. WARNING: setting this argument will caused unaligned memory access on the GPU, which may reduce performance. In this case, consider circshift-ing all BatchParams instead.
  • verbose::Bool: If true, print the the status of tracking. Default is false
  • groupsize::Int: Designates a group of threads acting in parallel, preferably in lockstep. If tracking on a CUDA GPU, this is equal to the "block" size. On the CPU, would be a multiple of the vector register width. Default is 0 which lets KernelAbstractions decide.
  • use_cpu_multithreading::Bool: If true, then CPU multithreading will be used. Only beneficial for a large number of particles, as there is a cost to launching threads. Default is false.
  • use_KA::Bool: If true, uses KernelAbstractions to launch tracking kernels. Default is true, and it must be true for the GPU.
  • use_explicit_SIMD::Bool: If true, uses SciBmad's explicit CPU SIMD tracking, which often guarantees vectorization of tracking on the CPU. Default is !use_KA

SciBmad.TrackResult — Type
struct TrackResult

Contains all information for a given particle tracking run. The particles are read at locations of the beamline (given as for the columns of twiss; without a location, the only saved location, by default the end of the beamline), for a saved turn and a particle:

res.x[turn=2]                     # x of all particles after turn 2 (at the only saved location)
res.x[turn=2, particle=1]         # of particle 1
res.x[]                           # [particle, saved turn]
res.px[qd, turn=2]                # at the beginning of the element qd (see `at` in `track`)
res.v[qd, :exit, particle=1]      # all six coordinates at its end: [coordinate, saved turn]

Properties

  • x, px, y, py, z, pz: the coordinates, v: all six (the coordinate is the second index), q: the spin quaternions if spin was tracked, state: the state of the particles (STATE_ALIVE, ...), t_ref, beta_gamma_ref: the reference time and energy (one value per location and turn) if save_reference=true. See TrackColumn for how they are read
  • turns: the saved turns (turn 0: the initial coordinates; NaN at the locations before start)
  • start: the beamline index of the element where the tracking started (see start in track)
  • s, index, name, kind: the s, the beamline index (-1 for the end of the beamline), the name and the kind of the element of each saved location
  • data: the saved arrays, indexed by location number (in the order of s) and saved turn (1: the initial coordinates): state[particle, location, saved turn], v[particle, coordinate, location, saved turn], q[particle, quaternion, location, saved turn] (or nothing), t_ref[location, saved turn] and beta_gamma_ref[location, saved turn] (or nothing; per particle with BatchParams: a BatchParam for each location and turn)
  • config: the TrackConfig, elapsed_time: the tracking time in seconds, bunch: the Bunch at the end of tracking

SciBmad.TwissColumn — Type
TwissColumn

A column of a Twiss table (e.g. tw.beta1), indexed with locations of the beamline exactly as the columns of a TwissExpr:

  • tw.beta1[qd], tw.beta1[5]: at the beginning of the element qd (one value; qd must be placed once in the beamline, else it is an error), or of the element with beamline index 5. Elements made from qd (copies, also of copies) are placements of qd
  • tw.beta1[[qd]]: at the beginning of every placement of qd, in beamline order (a vector)
  • tw.beta1[begin], tw.beta1[end]: at the beginning and the end of the beamline (or of the part of it given with start and stop). As an index, end is the beamline index of the end (one more than the number of elements, or the index of stop), so tw.beta1[end-1] is at the beginning of the last element
  • tw.beta1[5, :exit], tw.beta1[qd, :exit]: at the end of the element (the beginning of the next one). The end of the beamline is like a zero-length element: [end], [end, :entrance] and [end, :exit] are the same location
  • tw.beta1[5, :], tw.beta1[qd, :]: at every integration step of the element, both ends included (a vector)
  • tw.beta1[5, 2], tw.beta1[qd, 2]: two integration steps after the beginning of the element
  • tw.beta1["q*"], tw.beta1[r"..."], tw.beta1[[qf, qd]], tw.beta1[2:5]: at the beginning of the elements found by name (as for findelements), or of each element given (a vector). With a position, e.g. tw.beta1[[qd], :exit], at that position of each
  • tw.beta1[(2.0, 10.0)], tw.beta1[:]: at every integration step in an s-range (and the end of the beamline if the range contains it), or of the whole beamline (a vector)

In the table of a part of the beamline (start, stop), a vector has the locations in the part only, an element must be placed once in the part, and a beamline index outside it is an error. The table must have rows at these locations (it has with the default at). The column also iterates over all rows of the table, in order, and broadcasts (tw.dbeta1 ./ tw.beta1) as a vector of them; collect(tw.beta1) (or tw.df.beta1) is that vector, and first and last are its first and last rows.

SciBmad.TwissExpr — Type
TwissExpr(bl::Beamline; kwargs...)

The quantities of twiss(bl; kwargs...) as expressions (LatticeExpr), computed only when they are needed (by value, SciBmad.value_and_jacobian or match!), and then only at the locations used. kwargs are those of twiss (rf_on, a_initial, spin, delta0, ...) except at, cols, base_cols, as_taylor_series and GTPSA_descriptor, which are set from the expressions. The truncation orders are chosen from the quantities used; order can be given to use a higher one.

a_initial may be the a of another TwissExpr, e.g. TwissExpr(line; a_initial=tw.a[end]), to continue the lattice functions of another beamline. initial may be a Context, whose variables can then be knobs, e.g. to match the Twiss parameters at the start of a line: ini = Context(beta1=10.0, beta2=10.0), TwissExpr(line; initial=ini), @knob(ini.beta1).

Quantities

  • Summary values: tw.q1, tw.q2, tw.q3, tw.etac, tw.alphac, tw.qspin, tw.damp1, ... A derivative of an amplitude-dependent value is selected as for the result of twiss, e.g. tw.q1[delta=2] (∂²q1/∂δ²) or tw.q1[J1=1]; tw.dq1 and tw.dq2 are short for the chromaticities tw.q1[delta=1] and tw.q2[delta=1], tw.dq1_n for tw.q1[delta=n].
  • Columns: tw.<column>[location] for every scalar column of twiss, including chromatic derivatives (tw.dbeta1, tw.dx_2) and tw.h<ijkl>.

Locations

The same as for the columns of the result of twiss (see TwissColumn):

  • tw.beta1[ele], tw.beta1[7]: the beginning of the element (placed once, else an error), or of the element with that beamline index. tw.beta1[[ele]]: every placement (a vector).
  • tw.beta1[ele, :exit]: the end of the element.
  • tw.beta1[ele, :]: every integration step of the element, both ends included (a vector; tw.beta1[[ele], :] of every placement). tw.beta1[ele, k]: after k integration steps.
  • tw.beta1[end], tw.beta1[begin]: the end and the beginning of the beamline (or of the part given with start and stop, which vectors are restricted to). end is a beamline index: tw.beta1[end-1] is the beginning of the last element.
  • tw.beta1["q*"], tw.beta1[r"..."]: elements by name, as for findelements (a vector).
  • tw.beta1[(s1, s2)], tw.beta1[:]: every integration step in an s-range, or of the whole beamline (a vector).

Vectors are elementwise: tw.beta1["q*"]^2, tw.beta1["q*"] <= 30 (one target per element), with sum, mean, maximum, minimum and norm.

SciBmad.dynamic_aperture — Method
dynamic_aperture(ring::Beamline; kwargs...) -> NTuple{2,Matrix{Float64}}

Computes the acceptance of the ring by pushing a polar grid in x/sig_x and y/sig_y space, for each of the provided deltas. The beam sizes sig_x and sig_y are those at the beginning of the beamline for the given emittances. Returns a tuple of two matrices x_norm_da, y_norm_da: x_norm_da[j, i], y_norm_da[j, i] is the starting position, in units of sig_x and sig_y, of the first particle lost along the j-th angle of the grid for deltas[i]; Inf if no particle along that angle is lost, and the column i is zero if the particle on the closed orbit itself is lost. BatchParams in the lattice are not supported (an error: each particle of the grid would see another entry).

Required Keyword arguments

  • n_r::Int: Number of radial points of the polar grid, from 0 to the maximum: each angle has n_r - 1 particles, and the closed orbit one for each δ
  • n_theta::Int: Number of angles to sample on the polar grid (see theta_lims)
  • deltas::AbstractArray: Array of each δ to compute the transverse acceptance
  • max_sig_x::Real: Maximum sigma-x of the polar grid, in units of sigma (e.g. max_sig_x=20 to check up to 20 sigma)
  • max_sig_y::Real: Maximum sigma-y of the polar grid, in units of sigma (e.g. max_sig_y=20 to check up to 20 sigma)
  • emit_1::Real: Horizontal-like emittance to assume [m]
  • emit_2::Real: Vertical-like emittance to assume [m]
  • n_turns::Int: Number of turns to track

Optional Keyword Arguments

  • backend: A CPU/GPU device backend to use, e.g. CPU(), or CUDA.CUDABackend() to use the GPU. Default is CPU()
  • coordinates_number_type::Type: The type of the phase space coordinates to use in tracking. Default is Float64
  • delta_dependent_orbits::Bool: If true, then for each δ in deltas, the computed acceptance line will be centered around that δ-dependent closed orbit (computed with rf_on=false). Else, all acceptance lines are centered around the 6D closed orbit. Default is true if coasting beam is detected, false if longitudinal motion is detected. The tracking itself includes RF cavities in either case, unless rf_on=false is given too.
  • theta_lims: A tuple specifying the range of thetas to scan on the polar grid. Default is (0, pi), the upper half plane (y >= 0)
  • sig_pz::Real: sigma-δ of the beam to assume, default is 0
  • emit_3::Real: Longitudinal-like emittance to assume [m]
  • output_file: If provided, then a file containing the initial particle coordinates (w.r.t. the closed orbit(s)) as rows, with the last column specifying the particle state at the end of tracking, will be written to the file. Default is nothing.
  • track_kwargs...: Any of the settings in TrackConfig except for n_turns and save_every_n_turns may be provided to configure the tracking.

SciBmad.find_closed_orbit — Method
find_closed_orbit(bl::Beamline; v0=zeros(1, 6), kwargs...)

Finds the closed orbit of the beamline bl using the initial guess v0. Supports batched- closed orbit finding including BatchParams and/or different δ-dependent closed orbits in rings with coasting beam, simply by including more particles in the guess v0.

A named tuple is returned containing the following fields:

  • v0: The initial matrix v0, mutated to contain the result
  • coasting_beam: true if coasting beam, false otherwise
  • sol: Another named tuple containing Newton solver convergence information (see SciBmad.BatchSolve.newton), including the Jacobian(s) for the particle(s) at the last iteration.

This function is GPU-parallelizable by specifying v0 as a GPUArray (e.g. CuArray), and will use CUBLAS's batched linear system solvers for the Newton solve.

Keyword arguments

  • v0: Matrix of size (n_particles, 6) as the initial guess. If n_particles > 1, batched closed orbit finding will be used. NOTE: v0 will be mutated in place with the result! Default is zeros(1, 6).
  • reltol: Relative convergence tolerance of the Newton solver, default is 1e-13
  • abstol: Absolute convergence tolerance of the residual norm, default is 1e-13
  • maxiter: Maximum iterations for the Newton root finder before failure, default is 100
  • rf_on::Bool: If false, then any RFParams in any LatElements are ignored for the entirety of the tracking. Default is true.
  • batch_start::Int: Specifies the starting index for BatchParams that particles in a bunch will see. E.g., if batch_start=3, then particle 1 sees index 3 in all BatchParams, particle 2 sees index 4, etc. Indexing of BatchParams will loop around to the start if the particle index exceeds the length of the BatchParams. Default is 1. WARNING: setting this argument will caused unaligned memory access on the GPU, which may reduce performance. In this case, consider circshift-ing all BatchParams instead.
  • autodiff: Automatic-differentiation backend to use (e.g. AutoForwardDiff(), AutoEnzyme(), AutoGTPSA(), etc.). Default is AutoForwardDiff. See ADTypes.jl for all supported backends.
  • warn: If true, warnings about the result will be printed. Default is true
  • coast_tol: Tolerance for the first-order delta dependences on each of the phase space variables below which coasting beam is assumed. Default is 1e-14.
  • coasting_beam: Bool that can be optionally specified as true or false to bypass the coasting- beam check and save some computation time.
  • batch: Optionally specify if batched-solution is used as Val{true}() or Val{false}() to improve type-stability of this function.
  • prep: A DifferentiationInterface.JacobianPrep object to use for the automatic-differentation backend. Default is nothing meaning to construct one automatically using the autodiff backend

Examples

qf = Quadrupole(Kn1=0.36, L=0.5)
d = Drift(L=1.2)
qd = Quadrupole(Kn1=-0.36, L=0.5)
kick = HKicker(Kn0L=1e-5)

fodo = Beamline([qf, d, qd, d, kick], 
        species_ref=Species("electron"), E_ref=18e9) # some Beamline
co_sol = find_closed_orbit(fodo)

# To get delta-dependent closed orbits:
v0 = [0. 0. 0. 0. 0. 0.1e-2; # δ = 0.1e-2
      0. 0. 0. 0. 0. 0.2e-2] # δ = 0.2e-2

co_sol = find_closed_orbit(fodo, v0=v0)

# With BatchParams
kick.Kn0L = BatchParam([1e-5, 2e-5])
v0 = zeros(2, 6)
co_sol = find_closed_orbit(fodo, v0=v0)

# BatchParams + delta-dependent closed orbits:
v0 = [0. 0. 0. 0. 0. 0.1e-2; # δ = 0.1e-2
      0. 0. 0. 0. 0. 0.2e-2] # δ = 0.2e-2
co_sol = find_closed_orbit(fodo, v0=v0)

SciBmad.match! — Method
match!(; vary, targets=[], minimize=[], kwargs...) -> MatchResult
match!(bl::Beamline; vary, targets, twiss=(;), kwargs...)
match!(prob::MatchProblem; kwargs...)
match!(res::MatchResult; kwargs...)

Varies the Knobs vary (also obj => :property pairs) until the Targets targets are met, and leaves the lattice there. minimize are expressions whose sum of squares is made as small as possible together with the distances from the targets (each times its weight; the expressions times minimize_weight, default 1). Targets are written with expressions (LatticeExpr) of the quantities of a TwissExpr:

tw = TwissExpr(cell)
match!(vary=[@knob(qf.Kn1), @knob(qd.Kn1)], targets=[tw.q1 == 0.25, tw.q2 == 0.25])

Given a Beamline, targets (and minimize) may be functions of its TwissExpr (made with the twiss keyword arguments in twiss), which can also be written as a do block:

match!(cell; vary=[@knob(qf.Kn1), @knob(qd.Kn1)], targets = tw -> [tw.q1 == 0.25, tw.q2 == 0.25])

The derivatives are exact (see SciBmad.value_and_jacobian). The solver is the Levenberg-Marquardt method of BatchSolve (BatchSolve.levenberg_marquardt!): steps that do not reduce the residuals, or where the lattice has no solution (e.g. it is unstable), are rejected and shorter ones taken, so there may be fewer, as many, or more targets than knobs. Knobs stay within their bounds and step limits, and <= and >= targets only count while they are violated. Like every such method it finds a nearby solution: targets of very different size (a tune and a beta function) should get weights that make their residuals comparable. To use another optimizer, see MatchProblem.

Keyword arguments

  • maxiter: Maximum number of iterations, default is 50
  • verbose: If true, prints the progress of the solver at each iteration. Default is false
  • solver: :levenberg_marquardt (default), or :gauss_newton: Gauss-Newton steps from the singular value decomposition of the Jacobian (their halves, quarters and eighths, then damped steps, where a step does not reduce the residuals)
  • rcond: For solver=:gauss_newton, singular values of the Jacobian below rcond times the largest are ignored (knob combinations the targets do not respond to). Default is 1e-10

Returns a MatchResult. match!(res) continues the match from the current lattice.

SciBmad.phase_trombone! — Method
phase_trombone!(ele::LatElement; phi1=0, phi2=0, phi3=0)

Makes ele into a phase trombone - a matrix expanded around the current closed orbit (at the time of calling this function) which applies a linear rotation in normal form coordinates (which are also computed at the time of calling this function). Useful for creating zero-length elements where the phase advance can be tuned without impacting the linear optics. The LatElement must be in a Beamline in order to use this function.

phi1, phi2, and phi3 are the changes of the phase advances of the three normal modes, in units of 2π (i.e. the changes of the tunes). The LatElement property transport_map is filled with the corresponding phase trombone transport map, and transport_map_params with its parameters. The first three entries of transport_map_params are phi1, phi2, and phi3, and can be changed later to change the phase advances.

Spin tracking is NOT currently compatible with phase trombones.

Warn

If the closed orbit and/or linear optics at ele are changed after calling this function, then the phase trombone map is no longer valid.

SciBmad.track — Method
track(bl::Beamline; kwargs...) -> TrackResult

All-encompassing function to track particles through the beamline bl using the configured settings specified by the keyword arguments kwargs.

Keyword Arguments

  • v0: A matrix of size (n_particles, 6) storing the initial particle phase space coordinates
  • spin: If true, spin tracking will be enabled with identity quaternions as initial quaternions
  • q0: A matrix of size (n_particles, 4) storing the initial particle spin quaternions if spin tracking
  • weight: Optional vector of length (n_particles) specifying macroparticle weights per particle, default is nothing corresponding to uniform weights for all particles
  • species: The species of the particles, default the reference species of the beamline (bl.species_ref)
  • bunch: Instead of specifying v0, spin, q0, weight, and species, an initial Bunch may be explicitly provided
  • start::Union{Integer,LatElement}: The element (or its beamline index) at whose beginning the tracking starts. Default is 1
  • at::Union{Nothing,Colon,AbstractVector}: Where the particles are saved, as in twiss: a vector of locations, each as one index of a column (see TrackColumn): elements (at the beginning of each placement), beamline indexes, names (as for findelements), and s-ranges (tuples: the integrator steps inside them, and the end of the beamline if they contain it). : is every integrator step and the end of the beamline. An entry that is not in the beamline is an error. Default is nothing, only the end of the beamline. The locations are ordered in s (from the beginning of the beamline). The locations before start are first reached in the second turn: before (turns 0 and 1) they are NaN (state STATE_PREBORN)
  • n_turns::Int: Number of turns, each ending at the end of the beamline (the first turn begins at start), defaults to 1
  • save_every_n_turns::Int: Multiple of turn number which specifies the turns tracking data is saved, defaults to 1
  • in_body_coordinates::Bool: If true, particles saved inside misaligned elements are not transformed back to the reference curve coordinates. Default is false
  • save_reference::Bool: If true, the reference time and energy at each location and saved turn are saved too (t_ref and beta_gamma_ref of the result). This compiles the tracking separately and makes it slower (the reference time is computed at every integration step). Default is false
  • scalar_params::Bool: If true, only uses the primal values of any LatElement properties set as GTPSA.TPS, ForwardDiff.Dual, or ReverseDiff.TrackedReal (ignores derivatives part, useful for closed orbit finding prior to parametric normal form). Default is false
  • rf_on::Bool: If false, then any RFParams in any LatElements are ignored for the entirety of the tracking. Default is true
  • ramp_particle_energy_without_rf::Bool: If true when ramping (Beamline's reference energy is a TimeFunction), then particle energies will be artificially ramped with the reference energy. Default is false
  • ramp_update_each_particle::Bool: If true when ramping, then each particle sees the reference energy at its own time (from its z-offset) at the element entrances, and the reference energy also changes through each element. If false, all particles see the reference energy at the reference time at each element entrance. Usually only needed if ramping is fast compared to the time scale of bunch passage through elements. (Time-dependent element parameters are always evaluated at each particle's own time.) Default is false.
  • batch_start::Int: Specifies the starting index for BatchParams that particles in a bunch will see. E.g., if batch_start=3, then particle 1 sees index 3 in all BatchParams, particle 2 sees index 4, etc. Indexing of BatchParams will loop around to the start if the particle index exceeds the length of the BatchParams. Default is 1. WARNING: setting this argument will caused unaligned memory access on the GPU, which may reduce performance. In this case, consider circshift-ing all BatchParams instead.
  • verbose::Bool: If true, print the the status of tracking. Default is false
  • groupsize::Int: Designates a group of threads acting in parallel, preferably in lockstep. If tracking on a CUDA GPU, this is equal to the "block" size. On the CPU, would be a multiple of the vector register width. Default is 0 which lets KernelAbstractions decide.
  • use_cpu_multithreading::Bool: If true, then CPU multithreading will be used. Only beneficial for a large number of particles, as there is a cost to launching threads. Default is false.
  • use_KA::Bool: If true, uses KernelAbstractions to launch tracking kernels. Default is true if v0 is a GPU array, else false.
  • use_explicit_SIMD::Bool: If true, uses SciBmad's explicit CPU SIMD tracking, which often guarantees vectorization of tracking on the CPU. Default is !use_KA
  • config: Instead of specifying n_turns, save_every_n_turns, in_body_coordinates, save_reference, scalar_params, ramp_particle_energy_without_rf, ramp_update_each_particle, verbose, groupsize, use_cpu_multithreading, use_KA, and use_explicit_SIMD, a single TrackConfig struct can be provided instead. Setting any of these keyword arguments will override that in config.

track_spin(q::TrackColumn, s0::AbstractVecOrMat)
track_spin(q::AbstractArray, s0::AbstractVecOrMat)

Given initial spin(s) s0 and the quaternions res.q of a TrackResult res, returns a TrackColumn s of the particles' spin 3-vectors, read like res.q: e.g. s[turn=n, particle=i] is the spin of particle i after turn n (at the only saved location), s[qd, turn=n, particle=i] at the beginning of qd.

SciBmad.twiss — Method
twiss(bl::Beamline; kwargs...)

General function to compute the (parametric and nonlinear) optics of a Beamline. Returns a Twiss struct that contains the (amplitude-dependent) (spin) tunes/slip, and a dataframe of the lattice functions at each specified integration step. By default, lattice functions of the Sagan-Rubin/Edwards-Teng coupling formalism are computed in the dataframe at every integration step. The columns are read at locations of the beamline, e.g. tw.beta1[qd] at the beginning of the element qd (see TwissColumn), and the whole table is tw.df.

The cols keyword argument can be set to customize what quantities will be computed and stored as columns in the returned dataframe. E.g., 

tw = twiss(bl; cols=["beta1"])

will compute only the horizontal-like beta function. We can also specify so-called "resonance driving terms"/"detune coefficients" of the nonlinear effective Hamiltonian,

tw = twiss(bl; cols=["beta1", "h3000"], order=2)

where the total order of the twiss call has also been set appropriately to compute h3000 (without order and chrom, the orders that the columns need are chosen).

An arbitrary order chromatic derivative of any scalar-valued column can be taken using the syntax d<column>_<order>. If order==1, then the _1 can be omitted. E.g., the linear and 2nd order dispersions, as well as ∂β₁/∂δ can be computed with

tw = twiss(bl; cols=["dx", "dx_2","dbeta1"], chrom=2)

where the chrom keyword argument, which specifies solely the truncation order of δ, has been set appropriately.

Chromatic derivatives need a beam without synchrotron motion: rf_on=false if there are RF cavities.

To customize the output, such as computing higher order (chromatic) lattice functions, spin lattice functions/tune, amplitude-dependent tunes, and parametric quantities, see the keyword arguments:

Keyword arguments

  • at::Union{Colon, AbstractVector}: Where to compute the lattice functions (the rows of the table): a vector of locations, each as one index of a column (see TwissColumn): elements (at the beginning of each placement), beamline indexes, names (as for findelements), and s-ranges (tuples). Default :, every integration step and the end of the beamline. An entry that is not in the beamline is an error; in a part of the beamline (start, stop) only the locations in the part are computed.
  • start, stop: Elements (or their beamline indexes) to compute the optics of only a part of the beamline: from the beginning of start (default: the first element) to the beginning of stop (default: the end of the beamline). Without initial or a_initial these are the periodic optics of that part by itself (e.g. of one cell of a ring), with them those of an open line that starts at start. s and index in the table are those of the whole beamline, phases are counted from start, and the last row is the beginning of stop.
  • in_body_coordinates::Bool: If true the lattice functions inside misaligned elements are not transformed back to the reference curve coordinates. Default is false
  • rf_on::Bool: If false, then any RFParams in any LatElements are ignored for the entirety of the Twiss tracking and calculation. Default is true
  • order::Integer: TPSA truncation order for all phase space coordinates used in the Twiss calculation. If neither order nor chrom is given, both are chosen from cols (as TwissExpr does): 1 for the default columns, higher for chromatic derivatives (chrom) and resonance driving terms (order). Default is 1 if only chrom is given
  • chrom::Integer: TPSA truncation order for only δ, default is order if order is given
  • GTPSA_descriptor::Union{Descriptor,Nothing}: Custom GTPSA Descriptor to use for the Twiss calculation, required to provide to do parametric normal form and lattice function calculations. Default is Descriptor([order, order, order, order, order, chrom], max(order,chrom)).
  • initial: The lattice functions at the start of an "open" line (e.g. a transfer line), by name: beta1, beta2 (required), alpha1, alpha2, the coupling c11, c12, c21, c22, the dispersion dx, dpx, dy, dpy, and the orbit x, px, y, py, z, pz (all 0 if not given; pz is δ, else delta0), with the meanings of the columns of the same names. A NamedTuple, a Dict (with Symbol or String keys), a Context (whose variables can then be knobs of a match), or a row of another table (tw.df[end, :]; its other columns are ignored). The values may be Taylor series in GTPSA parameters, not in the phase space variables or δ. The beam has no synchrotron motion: RF cavities with voltage need rf_on=false (or a 6D a_initial). Default is nothing, to compute the periodic ("closed") lattice functions
  • a_initial::Union{DAMap,Nothing}: A DAMap of the initial transformation from normal form coordinates to laboratory coordinates, to compute the lattice functions of an "open" line (instead of initial). A coasting a_initial (without synchrotron motion) also needs rf_on=false if the line has RF cavities with voltage. Default is nothing
  • damping::Union{Bool,Nothing}: Specifies if radiation damping is included. Default is nothing, which will auto-detect from a_initial or the periodic a.
  • delta0: If the beam is coasting (no longitudinal oscillations), then the optics will be computed around this delta-dependent orbit. Else, this will be an initial guess for the 6D closed orbit calculation. Default is 0.. If a_initial is provided then this will be ignored, UNLESS a_initial is coasting, in which case this will set the value for δ. With initial, it is δ if initial has no pz.
  • v0: Initial guess for the closed orbit finder if a_initial is not provided, else setting this will override the orbit expansion origin coordinates in a_initial.v0. Not with initial, which gives the orbit.
  • spin::Bool: If true, spin is included in the Twiss calculation. Default is false, or true if a_initial includes spin.
  • base_cols: A vector of "base columns", that will always be included in the Twiss dataframe regardless of what is specified in cols. Defaults to the global variable SciBmad.base_cols, which defaults to ["index", "name", "kind", "s"].
  • cols: A vector of columns to include in the Twiss dataframe. See the extended help for all possible columns.
  • as_taylor_series::Union{Bool,Nothing}: If true, the lattice functions in the dataframe are returned as Taylor series types - this will be necessary if doing parametric normal form. Default is nothing, which autoselects to false if there are no parameters in the GTPSA, and true if there are parameters.
  • coast_tol: Tolerance for the first-order delta dependences on each of the phase space variables below which coasting beam is assumed, passed to find_closed_orbit. Default is 1e-14.
  • symplectic_tol::Float64: Tolerance of symplectic condition violation, above which radiation damping is assumed. Default is 1e-8.
  • batch_index::Int: If any element parameters are BatchParam, sets which index in the batch the twiss should be evaluated at. Default is 1. Batched element lengths and a batched reference energy are not supported in twiss yet.

To see a description of all quantities available to include in cols, see the extended help section using ??twiss

SciBmad.value_and_jacobian — Method
SciBmad.value_and_jacobian(exprs, knobs) -> (values, jacobian)
SciBmad.value_and_jacobian(exprs, knobs, x) -> (values, jacobian)

Not exported, because DifferentiationInterface exports a function of the same name: call it as SciBmad.value_and_jacobian.

The current values of the expressions (LatticeExprs) exprs and their exact derivatives in the knobs (Knobs, or obj => :property pairs): jacobian[i, j] is the derivative of exprs[i] (in the order of vec(exprs)) in knobs[j]. For a single expression, the value and its gradient are returned. With x, the knobs are first set to the values x (and stay there).

The derivatives are computed by automatic differentiation: the knobs are made parameters of the truncated power series (GTPSA) of one twiss call per TwissExpr, with the truncation orders the expressions need, and the knobs are set back to their values afterwards.
